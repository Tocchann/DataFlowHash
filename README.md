# Dataflow 重複ファイル検出

同じフォルダーを 4 つのモードで走査し、実行モデル・ハッシュ処理・バックプレッシャーが処理時間やメモリにどう影響するかを観察する WPF デモです。どのモードもファイルを書き換えたり削除したりしません。

## 起動

Windows と .NET 11 SDK が必要です。ビルド済みアプリの実行には .NET 11 Desktop Runtime を使用します。UI は Windows のライト／ダーク設定に追従する WPF 標準の Fluent テーマです。

```powershell
dotnet run --project .\DataflowDuplicateDetector\DataflowDuplicateDetector.csproj
dotnet test .\DataFlowHash.sln
```

フォルダーを選び、実行モードを指定して **開始** を押します。**停止** で走査をキャンセルできます。正常終了後はグループを選んで全パスを表示したり、**CSV 保存** から `Hash,Count,Path` 形式で出力したりできます。

## デモの進め方

| モード | 処理 |
|---|---|
| 逐次 | 1 ファイルずつフル SHA-256 を計算 |
| `Parallel.ForEachAsync` | 指定した並列度で全ファイルをフルハッシュ |
| Dataflow：全件フルハッシュ | 有界パイプラインで全ファイルをフルハッシュ |
| Dataflow：短縮ハッシュ | サイズと先頭 1 MiB が一致する候補だけをフルハッシュ |

1. **実行モデルを比較する。** 同じサイズで内容が異なるファイルと、別名のコピーを含むフォルダーを用意します。逐次・並列・Dataflow 全件版を実行し、フルハッシュ数が同じであることを確認して、経過時間・処理速度・CPU を比較します。並列版と Dataflow には同じ並列度を指定します。
2. **候補絞り込みを比較する。** 同じ並列度・容量で Dataflow 全件版と短縮版を実行します。先頭が異なるファイルが多い場合、短縮版ではフルハッシュ数が減ります。逆に、ファイルサイズと先頭 1 MiB が同じで末尾だけが異なるファイルは両方ともフルハッシュされ、重複にはなりません。短縮版でも最終判定はフル SHA-256 です。
3. **バックプレッシャーを観察する。** 数秒以上かかるフォルダーで Dataflow を選び、容量 1、100、より大きな値の順で比較します。入口キュー長、列挙側の送信待ち回数・合計時間、ワーキングセットを見比べます。容量が小さいと、1 ブロックに同時に入る処理数も制限されます。バッファ量の効果を比較したい場合は、並列度以上の容量同士も比較してください。

### パイプラインと指標

```text
列挙 → 有界入口 → メタデータ検証 → フル SHA-256 → 集約
                           ↘ 短縮版：先頭ハッシュ → 候補選別 ↗
```

列挙側は `SendAsync` で入口の受理を待ちます。下流が詰まると有界ブロックを通じて入口まで待機が伝わります。入口キュー長は最初のバッファだけを示し、送信待ちは即座に受理されなかった回数と終了済み待機の累計です。処理速度は直近のサンプル区間で処理が確定したファイル数を示します。短縮版で一致相手が見つからなかったファイルは走査完了時に確定します。

容量は候補索引や集約結果を含むプロセス全体のメモリ上限ではありません。CPU は論理プロセッサ数で正規化したプロセス使用率、メモリはプロセスのワーキングセットです。実行順と OS のキャッシュ、ストレージ、ファイル構成によって結果は変わるため、順番を入れ替えて複数回比較してください。走査中に変更されないフォルダーを使ってください。アクセス不能な項目はスキップし、配下の再解析ポイントはたどりません。
